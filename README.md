# 一网统飞平台

React + TypeScript 前端、Java 21 + Spring Boot 后端，按杭州一网统飞原型构建。采用一套后台、一套独立业务数据库，任务、计划、准入、线索都使用简化办理流程。

## 快速启动

正式服务器使用前后端合一的 `oneflight-app` 镜像，Java 同时提供 React 静态页面和 API，MySQL 与附件保留独立持久化。构建、发布、备份和回退见 [一体镜像生产部署](docs/PRODUCTION.md)；原有本地开发启动方式如下。

已安装 Docker Desktop 或 Docker Engine + Compose 时，在项目根目录执行：

```bash
./scripts/up.sh
```

打开 <http://localhost:8088>。首次启动生成私有 `.env`，登录账号为其中的 `BOOTSTRAP_ADMIN_USERNAME`，初始密码在 `BOOTSTRAP_ADMIN_PASSWORD`。不要把 `.env` 上传到 Git。已有管理员不会因重启被重新初始化。

本地开发需 Node.js 24、pnpm 10.33.0、Java 21、Maven 3.9+：

```bash
./scripts/dev.sh
# 使用独立 MySQL 容器进行开发
./scripts/dev.sh --mysql
# 仅开发前端，API 使用已运行的 Docker 后端（与 8088 共用附件卷）
./scripts/dev.sh --container-api
```

前端地址 <http://localhost:5173>，后端 <http://localhost:8080>。默认开发数据库为 `backend/data/oneflight` 中的持久化 H2，正式部署使用 MySQL 8.4。Ctrl-C 结束开发服务；MySQL 数据卷保留。

原生 `--mysql` 模式不能与使用同一业务库的 Docker 后端并行写入，脚本会检查并阻止。需让本机 Java 与容器共享附件目录时，使用 `./scripts/up.sh --shared-uploads`；该模式只用于开发，默认部署仍使用命名文件卷。

## 功能与真实数据

覆盖态势感知、任务调度、飞行管控、飞行服务、资源管理、飞行算法、场景应用及平台设置。人工资源分配，一次审核，需求部门验收任务；任务执行进度与外部飞行遥测分别管理。

通过后端适配器读取授权设备、航线、源库飞行记录、执行记录、MQTT 遥测及算法目录。来源地址与凭据在 `.env` 中配置，具体字段见 [数据接入说明](docs/INTEGRATIONS.md)。未配置或不可用的数据源显示真实状态；媒体流及训练等未接通能力保留未接入说明。飞行作业按钮在关联计划审批通过、任务和设备匹配且账号有执行权限时可点击，操作只更新页面状态并提示“未发送设备指令”，不调用设备 API，不改变任务进度或遥测。物理命令接口仍返回 `PROVIDER_NOT_CONFIGURED`。正式运行不注入样例业务记录。

## 项目结构与验证

“指挥大屏”使用独立的低空运行指挥布局，展示资源、运行健康、任务、空域、累计飞行指标及任务分布图表。飞机位置和航迹由带设备编号、观测时间、经纬度及明确高度基准的上报点驱动；当前 demo 由独立本地数据源每秒产生上报，按设备累积历史路径，保留暂停、跟随、近览和关闭操作。通过同一前端报告入口可替换数据源，尚未接通真实设备轨迹流；业务指标仍读取授权数据。返回按钮或 Esc 可回到进入大屏前的页面。

大屏卡片会展示当前区域对应的资源、任务、线索或计划明细，累计指标可查看设备贡献。资源列表与地图对象联动，航空器、起降点、航线和空域支持选中高亮、重复定位及详情；定位业务对象会退出飞行跟随，避免争抢镜头。Esc 优先关闭弹窗或对象详情，再退出大屏。数据保障可查看各来源同步状态并手动刷新。

| 目录 | 内容 |
| --- | --- |
| `frontend/` | React 页面、地图、业务表单、公共组件 |
| `backend/` | 鉴权、业务状态流转、权限控制、JPA、Flyway、来源适配器 |
| `compose*.yaml` | 正式部署、离线部署与本机开发配置 |
| `scripts/` | 开发、容器启动、AMD64 离线打包、备份恢复 |
| `docs/` | 架构、接口、部署和接入说明 |

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm run build
pnpm test
cd ../backend
mvn -B -ntp test
```

API 前缀为 `/api/v1`，OpenAPI 地址为 `/v3/api-docs`，Swagger UI 为 `/swagger-ui/index.html`。API 的写入请求使用会话和 CSRF 校验；前端已封装凭据及 `X-CSRF-TOKEN` 请求头。

详细说明：[部署、备份与回退](docs/DEPLOYMENT.md)、[架构和业务约定](docs/ARCHITECTURE.md)、[接口约定](docs/API.md)、[部署验证记录](docs/DEPLOYMENT-CHECKS.md)、[最终验收记录](docs/ACCEPTANCE.md)。


来源档案导入与业务初始化见 [DATA-INITIALIZATION.md](docs/DATA-INITIALIZATION.md)。人员从 ja-4a 的授权设备关联组织读取，资质未核验时保留未知；初始化业务记录使用正常业务名称，在详情保留“平台初始化录入”。原件、上游行动和识别观测的核验范围见 [REAL-SOURCE-VERIFICATION.md](docs/REAL-SOURCE-VERIFICATION.md)。


日常使用以“任务调度”为主入口：提交需求 → 分配设备和飞手 → 登记执行 → 提交成果 → 需求部门验收。任务页签和详情使用同一组状态词，详情直接显示下一步；查看设备运行会带入本单的来源设备，返回后仍是原任务。设备只需完善一次调度资料，人员档案与有执行权限的账号分别管理。已批日常或长期计划也可在飞行服务直接“安排执行任务”，一计划可安排多次，随后进入同一分配、执行、成果和验收流程；任务继承计划组织与区域，时段须位于计划范围内。计划详情可查看全部子任务，任务详情可返回原计划。准入和咨询按需办理，来源行动只读查看。

管理员或运营调度可在任务待分配、待执行时关联同组织、同区域且时段覆盖任务的日常或长期计划；关联计划不改变任务阶段。开始飞行任务执行前必须取得计划审批，资料核对工作按独立本地业务办理。关联计划审批通过，任务处于待执行或执行中，设备和执行权限核对通过后，“下发任务、立即起飞、暂停作业、立即返航、确认落地并结束”以及云台、喊话可作页面交互。按钮点击不调用设备 API，不登记实际起降、任务完成或设备执行成功；任务进度仍通过原业务动作办理。计划未通过、退回或取消，或资料读取失败、任务结束、设备不匹配时重新锁定。需求部门及未被指派的飞手不能操作。

分配资源时会列出当前可见设备的可调度、待确认数量，以及不可用原因。选择设备后只允许选择符合任务区域、组织、设备授权和时段要求的飞手；不匹配会在提交前说明具体原因。导入的设备需在“资源管理”完善调度资料，飞手的可见 / 执行区域和设备授权在“平台设置 → 组织与权限”维护，来源接入不会自动完成这两项配置。


页面下拉框统一采用深色控件，支持选中勾选、禁用原因、较多选项搜索及键盘操作；弹层根据可用空间上下展开。只读验收工具 `scripts/qa-select-ui.mjs` 与共用的 `scripts/lib/select-ui.mjs` 随离线包提供，运行时需完整源码、前端开发依赖及可用 Chrome；部署服务本身不依赖这些开发工具。

航线、空域资源采用加宽编辑窗口，并可进入全屏绘制。航点编号、起终点和路线描边便于辨认，支持地图添加、拖动、点选定位及经纬度调整；切换视角、底图或返回表单保留本次编辑。编辑已有来源数据时保留航点高程、额外坐标维度及 Polygon 内环，不把规划值写入来源坐标第三维。

3D 航线以绿色空中连线、三角航点及白色垂地虚线显示。飞行高度采用独立 `geometryContext.flightProfile` 保存的 AGL（相对航点地面）规划值，默认 100 米，可逐点修改或统一应用，新增航点继承统一默认值。规划高度是本地设置，来源坐标 Z 和 `heightMeters` 的基准未知时只读保留。地形 DEM 尚未就绪的点明确提示按零高程基面预览，这种预览不代表已取得真实海拔。

打开真实来源长航线时默认进入当前航点的局部高度视图，避免数十公里全线缩放使百米高度无法辨认；“全线总览”查看完整范围，“立体近览”回到所选航点及相邻局部航段。地面投影、高度幕帘、真实规划高度标注可分别开关，随地图旋转和缩放同步投影；显示效果不夸大或改写实际 AGL 值。编辑卫星影像采用更清楚的亮度与对比，其他地图保留原配色。

“查看楼宇”读取 OpenFreeMap 的真实 OpenStreetMap 建筑轮廓，可查看资料并关联当前航点；未提供高度时保存 `null`。楼宇关联是位置参照，数据覆盖与高度以来源为准，不代表已完成净空或航线安全校验。飞行管控将最近有效观测的在线设备置顶，首次默认优先选中在线设备，轮询刷新保留当前查看对象；从任务或指定设备进入时仍打开对应设备。

完整源码的前端构建可通过 `VITE_BUILDING_SOURCE_URL` 覆盖兼容的楼宇矢量 TileJSON 来源，默认使用 OpenFreeMap；此项在构建时读取。

只读页面验收工具 `scripts/qa-route-editor.mjs` 覆盖绘制、全屏、楼宇关联、在线排序及任务设备定位；`scripts/qa-route-3d.mjs` 检查立体航线、高度交互、来源保留和各尺寸布局；`scripts/qa-route-clarity.mjs` 使用真实长航线检查默认百米高度、近览/总览、空间辅助与各尺寸的清晰度。运行需要完整源码、`frontend` 开发依赖和可用 Chrome；离线部署包仅附工具脚本，不含这些浏览器开发依赖，业务写请求会在验收浏览器中被阻止。
