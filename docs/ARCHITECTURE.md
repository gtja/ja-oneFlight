# 架构与业务约定

采用 React/TypeScript 单页应用、一个 Java/Spring Boot 应用和独立 MySQL 8.4 业务库。开发环境可使用持久化 H2；真实来源通过 HTTP、只读 JDBC 和 MQTT 适配，不复用 `ja-oneflight-demo` 业务实现。

## 一体镜像托管与静态资源

生产根 `Dockerfile` 将 Vite 产物放入 JAR 的 `classpath:/static/`，由同一非 root Java 21 JVM 提供页面和 API；运行时只需 `app/mysql` 两个服务，MySQL 与 uploads 各自使用持久卷。原三服务方案继续用于本机开发与已有交付；正式服务器的固定项目及维护方式见 [PRODUCTION.md](PRODUCTION.md)。

正式项目 `oneflight-prod` 的业务库 `oneflight` 及 uploads 卷与本机项目隔离，不迁入本机测试业务。来源地址通过私有 `.env` 配置；同机服务可使用等价内网地址，来源账号权限不随网络地址改变。算法目录按用户选择使用本机来源，实际读取与部署证据见生产发布记录。

Spring Security 仅对页面入口、`/index.html`、`/logo.svg`、`/assets/**` 和 `/healthz` 放行 GET/HEAD，API 继续使用会话、权限及 CSRF 校验；原健康、登录与 OpenAPI 白名单保持独立。不把静态资源放行扩展到写请求，静态资源不存在时保留 404，不把 API 或缺失资源改为返回 SPA 页面。

带内容摘要的 `/assets/**` 设置一年 `public, immutable` 缓存；入口 `index.html` 与 `logo.svg` 使用 `no-cache`，让新发布入口及时重新校验。安全响应头保留内容类型保护，并设置 `strict-origin-when-cross-origin` Referrer Policy。`/actuator/health` 用于应用就绪检查，`/healthz` 只保留原页面存活兼容语义；托管方式不改变业务授权、来源权限或物理设备命令边界。

## 业务流转

| 业务 | 流转 |
| --- | --- |
| 任务 | 待分配 → 待执行 → 执行中 → 待验收 → 已完成 |
| 任务退回 | 受理退回后补正重提；验收退回后补充成果再验收 |
| 计划/准入 | 待审核 → 通过或退回补正；一次审核、手工登记外部回执 |
| 行业线索 | 待复核 → 待处置 → 已归档；无效线索说明原因后归档 |
| 咨询 | 待答复 → 已答复 → 已完成 |

每个任务分配一台设备和一名飞手，校验执行时段冲突。任务开始/结束只改变本系统办理进度，不能下发真实起飞或返航。历史、操作者及办理时间留存。

分配候选由后端按当前任务计算，和提交 `ASSIGN` 共用规则：可见设备的调度状态、组织，飞手启用状态、组织、执行区域、设备授权，以及双方的时段占用。设备驻地区域本身不被当作飞手执行区域授权。页面保留不可用记录及原因，设备选择后联动飞手，避免仅按组织独立下拉而提交后才发现不匹配。来源导入保留待确认状态，账号和授权须通过正常管理流程维护，不在候选查询中自动激活或授权。

管理员与运营调度可对待分配、待执行任务办理 `LINK_PLAN`，关联同组织的日常或长期计划。后端检查任务与计划的权限、计划 ID、类型及有效业务状态、同组织同区域，以及任务时段完整包含在计划时段内，仅更新关联并留履历，任务阶段不变。关联未审批计划不会解锁作业按钮。

页面作业交互使用独立的审批门槛：任务分配的本地设备档案与当前来源设备一致、档案可调度、执行人员已分配、任务在待执行或执行中、所关联日常/长期计划审批通过，并且操作者为管理员、授权调度或本任务飞手，组织/区域/设备范围匹配。任务和计划的组织、区域及时段包含关系同时匹配。一个已批计划可以覆盖多次执行任务，旧主任务引用不构成排他条件。加载失败、资料不匹配、审批退回或取消、任务结束等情况回到锁定状态。

五个作业按钮与云台、喊话仅改变 React 状态并提供点击反馈，不调用设备 API、不持久化操作结果，也不改写遥测或任务阶段。“确认落地并结束”的页面点击不会办理本地 `FINISH`，也不证明实际落地。业务进度、源设备观测和物理命令适配器分别管理；物理命令网关保持未配置，后端命令接口仍为 501。

## 已批计划与多次执行

日常或长期计划通过一次审核后，管理员、调度和需求部门可从该计划安排单次执行任务，继承组织、区域及计划关联并进入待分配。长期计划可安排多次，随后逐单分配、开始、提交成果、退回补充和需求部门验收；计划台账分页展示全部可见子任务，任务页可按计划筛选并返回原计划。

`Task.planId` 是一计划多任务的权威关联。旧 `Plan.taskId` 仅作为兼容主任务引用，保存时安全同步；普通计划编辑者不能借此改绑其他任务。计划编辑和提交会核验全部已关联任务，不允许缩小有效期或改变区域导致子任务失配。任务基础资料保存、提交、分配、换绑和开始执行使用同一 `FlightPlanTaskPolicy`，校验日常/长期类型、有效状态、同组织同区域和时段包含；开始执行另须已审批。仅无计划的“资料核对”场景保留本地资料办理例外，不据此解锁飞行作业控件。

计划安排接口在事务内锁定父计划，按不可变来源计划 ID 与 UUID 请求键建立唯一索引，并保存内容摘要。相同操作者和内容重试返回原任务；同键不同内容或操作者拒绝为 409。后续换绑当前计划不会改变最初的幂等来源键。Flyway V5 只新增关联请求列和索引，不自动重写已有任务关系。

## 权限和数据

指挥大屏采用独立 React 页面和 `FlightSimulation3D` 组件，恢复普通业务地图与面板样式。业务面板按当前授权范围读取完整分页目录，区域筛选统一应用于业务统计及地图对象；今日任务图表以 Asia/Shanghai 的计划开始时间分组。

飞行展示的数据源与渲染分离。`flightReports.ts` 定义带设备 ID、UTC 毫秒观测时间、WGS84 经纬度、米制高度和显式 AGL/AMSL 基准的 `AircraftPositionReport`。本地 demo 每秒产生一次报告，经相同的历史归并和渲染链路展示；不写入设备、任务、遥测或飞行统计。机位只在已收到的位置点之间平滑，并钳制在最后报告位置；历史航迹按观测时间连线，不预绘未来路线、不按尾迹窗口消失。高度基准切换时断开连线，避免混接不同基准。

`FlightMap` 的可选 `flightReports` 接收增量报告批次，`aircraftDefinitions` 提供名称/机型，`flightStreamKey` 标识飞行会话。未提供 `flightReports` 且开启 `simulation` 时使用 demo；显式传入 `[]` 表示外部数据入口没有新报告，保留已有历史，初始为空时不生成飞机。相同设备的报告按观测时间排序，相同时间戳以新值更正；每机最多保留最近 10000 点。切换 `flightStreamKey` 才重置会话；暂停展示时继续收取外部报告，恢复后显示最新已知数据。切换底图不清空历史，关闭或卸载释放渲染资源。

后续接入时应把真实位置观测映射到 `flightReports`，优先使用 `positionObservedAt`，不把仅电量/在线状态刷新的 `lastObservedAt` 当成新位置时间；高度基准需按来源协议明确提供。现有后端轨迹流尚未接通，本轮只提供可替换的前端入口。

角色包括管理员、运营调度、需求部门、飞手。管理员管理全平台；调度分配和审核；需求部门提报及验收本部门任务；飞手办理指派任务。默认仅可访问本组织，调度跨组织办理须由管理员显式授权可见组织范围；区域、设备范围独立检查。权限在后端检查，不能依赖前端按钮隐藏。

执行飞手通过本人任务的 `planId` 取得关联计划的只读可见性，并继续检查组织及区域；不要求计划同时填写反向 `taskId`。读取关联计划不扩大写权限，非创建者不能因此编辑、提交或取消计划。

外部设备查询范围取来源授权和本地账号允许设备的交集。来源凭据只保存在后端，不返回至公开配置、浏览器、日志或镜像。外部 ID 使用字符串，时长为秒，距离为米，未知字段保留未知，不以零替代。

目录及来源权限每 60 秒刷新；遥测页面每 5 秒轮询。MQTT 使用独立客户端 ID 和精确设备主题。60 秒无更新或断连时状态未知，保留末次观测时间；上报、任务办理、实际起降时间分别存储及展示。

正式运行保留本系统记录、真实来源及用户授权的初始化工作项，各自记录来源。测试样例留在测试代码中。物理命令、轨迹、媒体流、训练或部署能力只有在独立适配器完成真实联调后才可接通；当前审批后解锁的页面交互没有连接物理命令网关。
