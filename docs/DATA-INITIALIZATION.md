# 来源导入与本地业务初始化

真实来源档案与平台初始化工作项分开保存。设备、人员、航线、空域及组织来自管理员明确调用的 `/api/v1/source-data/import`，保留来源系统、来源 ID、原始时间和 `SOURCE_IMPORTED`（兼容早期 `SOURCE_IMPORT`）。导入默认 `PENDING_CONFIRMATION`，不会建立实名登录账号、认定人员资质或授予组织权限；既有手工档案保持原状。

`scripts/seed-business.mjs` 建立正常名称的本地工作项，详情注明平台初始化录入，来源为 `BUSINESS_INITIALIZATION`。其中三个资料核对任务根据实际读取及文件校验办理本系统进度，不把这些工作项标成源库业务、真实飞行完成、监管审批结果或训练成功。

## 运行前提

使用 Node.js 20 或更新版本及已升级的 Java API。脚本读取私有 `.env` 中的管理员账号和密码，通过登录会话、CSRF 和正常 API 操作；不直连数据库、不执行来源导入、不执行真实设备控制。密码不写入命令参数或控制台。

先备份正常库，再由管理员导入所需真实档案。应用前至少需要当前本地组织下的两台真实 UAV 调度档案、一条真实来源人员档案、一条真实来源航线，以及非空真实算法目录。已有手工人员档案不会被替换。来源人员仍待资格核验，不会被批量激活或转为登录飞手。

后端须支持任务、计划、线索、咨询和账号的 `provenance` 输入及列表输出；维护、数据集和训练资源通过 `metadata.provenance` 传递。输入仅含 `origin`、`key`、`description`，后端增加 `recordedAt`、`recordedBy`，业务记录 `createdBy` 取真实操作者。新建记录留下 `INITIALIZE` 审计；办理动作使用正常状态流转，每次附“平台初始化登记”说明。

## 预览与应用

默认只预览，无业务写入，也不生成岗位密码：

```sh
node scripts/seed-business.mjs
node scripts/seed-business.mjs --region 余杭区 --date 2026-10-16
```

预览列出计划标题、类型、目标状态、复用情况和阻塞条件，不输出真实人员字段或登录密码。默认日期为上海时区次日，默认工作区域为余杭区；区域用于本地初始化安排，不代表来源设备行政归属已被核验。应用前应检查并按实际安排指定。

只有明确传入 `--apply` 才创建记录：

```sh
node scripts/seed-business.mjs --apply --region 余杭区
```

需要把两个已选真实来源设备档案从“待确认”启用为本地可排班档案时，增加 `--activate-devices`。它只改这两条档案，保留来源元数据，将本地排班区域设为指定区域并在备注说明这不是来源行政归属认定；不更改维护中、停用等人工设置的状态，也不启用真实控制。没有可用设备时，排班及资料核对任务保留待分配并在结果说明。

```sh
node scripts/seed-business.mjs --apply --activate-devices --attach-snapshots
```

`--attach-snapshots` 可把当前真实设备累计统计与航线档案信息生成 CSV，分别上传至一条未执行任务和一条待复核线索。未知值留空，文件说明其为档案读取快照；它不是现场成果或已确认的执法证据，不会推进执行、验收或归档。

真实原件默认从 `.local/real-data-audit/verified-media-manifest.json` 读取，可用 `--media-manifest` 指定清单。脚本重新核对允许目录下的普通图片文件、大小、图片签名及 SHA256；不把图片重新生成或改写观测时间。原件仅上传至“媒体归档核验”任务，且在其 `FINISH` / `ACCEPT` 前上传；没有对应场景证据的行业线索保持待补资料，不配不相关图片。成果记录实际核对数量和原件 SHA256，不认定拍摄时间或真实架次关联。

脚本另读取当前 `/config` 与 `/settings`，只为缺少且当前值非空的 `platformName`、`defaultRegion`、`mapStyleUrl`、`mapSatelliteUrl`、`mapTerrainUrl` 建立配置项，保留用户已有配置。

部署到其他站点或隔离验证环境时可指定 `--base-url`、`--env-file`、`--state-dir`。远程地址须为 HTTPS；HTTP 仅允许回环地址。初始化不会跟随登录重定向，避免将私有会话带到其他站点。

三个实际资料核对任务分别为“授权设备资料核对”（`EXECUTING`）、“航线索引核对”（`PENDING_ACCEPTANCE`）和“媒体归档核验”（`COMPLETED`）。本次实际核对 287 条授权设备档案、127 条航线索引（114 条可读几何）及 3 份大小与 SHA256 相符的原件。`START`、`FINISH`、`ACCEPT` 仅记录这些本地资料工作的办理进度，不表示真实飞行、起降或现场执法已完成。

样本与训练事项的 `algorithmId` 取真实目录。`sourceEventId` 从按真实类型查询的 `fire_detection`、`smoke`、`car` 事件中选择匹配项；不可用时保留空值，不填造事件 ID 或图片数量。真实事件不保证原图可下载，也不表示标注或人工确认已完成。

脚本建立运营调度、需求受理、飞行排班三个**本地流程岗位**，与真实来源人员档案分开。岗位仅限当前组织、指定区域及两个设备档案，不授予其他组织范围。飞行排班岗不是实名认证飞手，关联的待执行任务仅表达本地排班准备。

岗位随机密码仅写入 `.local/business-initialization/accounts.json`，目录权限 700、文件权限 600。状态与已选设备 ID 保存在同目录 `state.json`。不要把这些私有文件放入源码、镜像或离线包；初始化不会修改管理员密码。

## 幂等与中断处理

记录以稳定的 `provenance.key`（`oneflight.business-initialization.v1:类型:工作项`）识别，不按标题覆盖。复跑保留已有记录、人工办理后的状态和密码，不重置任务，也不覆盖既有真实档案。两个设备的选择会固定在私有状态文件中；设备不再可见时停止，不自动换一批设备或扩大授权。

同一私有状态目录有运行锁，避免本机并发执行。其他主机也不要对同一业务库并发初始化。进程异常退出留下 `.lock` 时，先确认对应进程已结束，再人工移除锁后重新预览。

每条记录的创建与办理是独立 API 事务。脚本逐步记录自己的创建及办理检查点，只有记录 ID、状态和 `updatedAt` 与未完成检查点一致、且重新读取确认未改变时才恢复余下步骤。已有人工修改或未知结果的记录保留，不自动推进，操作者可检查履历后正常办理；脚本不会为了补齐状态伪造执行或审批。附件按关联记录与稳定文件名去重，已完成任务不再上传。

预览的 `blocked` 非空时，`--apply` 在任何业务写入前退出。源码准备阶段完成脚本语法检查及正常库只读预览；正常业务库的应用由本轮执行操作者显式运行 `--apply`。

## 首次应用结果（2026-10-15 历史快照）

首次实际应用新增 27 项业务记录：任务 9、计划 4、线索 4、咨询与培训 4、维护/样本/训练资源合计 6；另创建本地流程岗位 3、附件 5、缺省平台配置 3。此前来源导入的真实档案与既有手工人员档案保持原状。

随后以同一私有状态目录重复执行，新增记录、办理动作、附件上传及配置写入均为 0。此结果确认按来源键去重且未重置已办理状态；本次未生成外部回执、资质证照、训练成功记录或真实控制成功记录。


## 计划与任务时段校验更新

当前版本在创建初始化任务时按任务日期选择同组织、同区域且完整覆盖任务时段的日常或长期计划；找不到匹配计划时不绑定错误日期计划。三个“资料核对”任务保持 `planId=null`，本地资料办理不借用飞行计划审批，也不解锁设备页面作业控件。脚本回归测试 4/4 通过。

已有记录的来源键及人工办理状态仍保留，重跑不会批量纠正历史关系。当前部署在完整备份后，由管理员通过正常 `LINK_PLAN` 为两条本方初始化的待执行巡查任务改绑到覆盖其时段的已批长期计划，并逐条留下审计；该长期计划现有 2 条关联执行任务。没有改写用户历史任务、计划审批或飞手授权。备份和具体 ID、操作响应保存在私有目录，不进入交付包。

后续从已批计划新增执行任务应使用 `POST /api/v1/plans/{id}/tasks`，每次安排使用新 UUID；失败重试沿用原 UUID 与原内容。任务时段、组织和区域受计划约束，安排本身不记录实际飞行或成果验收。
